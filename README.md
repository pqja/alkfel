# تطبيق الكافل — دليل التشغيل والرفع على GitHub

التطبيق مبني بملفين فقط: `index.html` و `app.js`، بدون أي حاجة لخطوة بناء (build)، لذلك رفعه على GitHub Pages مباشر جدًا.

## 1) رفع المشروع على GitHub Pages

1. أنشئ مستودع (Repository) جديد على GitHub، وارفع الملفين `index.html` و `app.js` إلى جذر المستودع.
2. من إعدادات المستودع: **Settings → Pages**، اختر المصدر `Deploy from a branch`، واختر الفرع `main` والمجلد `/root`.
3. بعد دقيقة أو دقيقتين سيصبح رابط تطبيقك: `https://USERNAME.github.io/REPO/`.

## 2) تفعيل تسجيل الدخول في Firebase (مهم جدًا)

اذهب إلى [Firebase Console](https://console.firebase.google.com) → اختر مشروعك `alkfel-f32cd`:

### أ) تفعيل طرق الدخول
Authentication → Sign-in method → فعّل:
- **Email/Password** (لأجل تسجيل الدخول وإنشاء حساب)
- **Google** (لأجل زر "المتابعة عبر جوجل")، وحدد بريد دعم للمشروع عند الطلب.

### ب) إضافة نطاق GitHub Pages إلى القائمة المسموحة
Authentication → Settings → Authorized domains → أضف:
```
USERNAME.github.io
```
بدون هذه الخطوة، سيفشل تسجيل الدخول بجوجل بصمت (خطأ unauthorized-domain).

## 3) إنشاء قاعدة بيانات Firestore

Firestore Database → Create database → ابدأ بوضع **Production mode** (سنضبط الصلاحيات بأنفسنا عبر ملف `firestore.rules` المرفق).

بعد الإنشاء، اذهب إلى تبويب **Rules** والصق محتوى ملف `firestore.rules` المرفق مع المشروع، ثم اضغط **Publish**.

هذه القواعد تضمن:
- كل مستخدم يرى بياناته فقط ولا يقدر يلمس بيانات غيره.
- فقط بريد المالك (`mslmalmyaly223@gmail.com`) يقدر يضيف/يحذف حملات، يضيف طرق دفع، أو يوافق/يرفض التبرعات.
- بدون هذا الملف، أي شخص يفتح أدوات المطوّر بالمتصفح يقدر يتلاعب بالبيانات — لذلك رفعه على Firestore **إلزامي وليس اختياري**.

## 4) كيف يعمل تخزين الصور (بدون Firebase Storage)

كما طلبت بالضبط: **لا يتم استخدام Firebase Storage إطلاقًا**. جميع الصور (سكرين شوت التحويل) تُضغط داخل المتصفح وتُخزَّن كنص (Base64) مباشرة داخل مستند Firestore. صور الحملات تُخزَّن كرابط (URL) نصي يدخله المالك بنفسه (مثلاً رابط صورة من أي مستضيف صور تفضّله).

## 5) لماذا هذا التصميم اقتصادي في القراءات (لـ5000 مستخدم نشط يوميًا)

- الحملات وطرق الدفع تُقرأ مرة واحدة وتُخزَّن في `localStorage` على جهاز المستخدم لمدة 5 دقائق؛ لا تُعاد قراءتها من Firestore إلا بعد انتهاء هذه المدة أو بعد تعديل المالك لها.
- الإشعارات تُقرأ فقط بمستمع واحد خفيف لكل مستخدم مسجّل دخول (وليس بشكل متكرر) طوال الجلسة.
- "تبرعاتي" و"مراجعة التبرعات" تُقرأ عند فتح الصفحة فقط، وليست مستمعًا دائمًا.
- عداد "طلبات قيد المراجعة" الذي يظهر كنقطة حمراء عند المالك فقط يستخدم `limit(1)` بدل قراءة كل الطلبات.

## 6) بريد المالك (لوحة التحكم)

زر "لوحة تحكم المالك" لا يظهر إلا لصاحب البريد:
```
mslmalmyaly223@gmail.com
```
هذا الشرط مطبّق في الواجهة (`app.js`) **وأيضًا** في قواعد الأمان (`firestore.rules`) حتى لا يقدر أي شخص آخر الوصول حتى لو عدّل كود المتصفح.

## 7) بنية البيانات في Firestore

```
users/{uid}
  name, email, phone, role, donatedTotal,
  lastNameChange, lastEmailChange, lastPhoneChange, createdAt
  └── notifications/{id}: { text, read, createdAt }

campaigns/{id}
  name, image (رابط), details, target, raised, createdAt

paymentMethods/{id}
  name, number, createdAt

donations/{id}
  uid, donorName, type ("صدقة" أو اسم الحملة), campaignId,
  amount, paymentMethod, screenshot (Base64), status (pending/approved/rejected),
  createdAt, reviewedAt
```

## 8) ملاحظات

- الجلسة تبقى محفوظة (`browserLocalPersistence`) حتى يضغط المستخدم "تسجيل الخروج" بنفسه.
- تم تعطيل تحديد النص والتكبير/التصغير بالكامل ليبدو التطبيق كتطبيق حقيقي وليس موقعًا.
- التصميم متجاوب بالكامل: على الهاتف يملأ الشاشة، وعلى الأجهزة الأكبر (لابتوب/كمبيوتر/آيباد) يظهر داخل إطار يشبه شاشة تطبيق بدل أن يتمدد كموقع ويب عادي.
- ميزة "تعيين اللغة" تُغيّر الاتجاه والتسميات الأساسية؛ يمكن إضافة ترجمة نصية كاملة لاحقًا لكل شاشة إذا احتجت ذلك.
